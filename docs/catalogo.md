# Catálogo y procedencia

## Construcción

`python scripts/build_catalog.py` importa las páginas 0 y 1 del [listado público paginado de SteamSpy](https://steamspy.com/api.php?request=all&page=0) como etapa 0. Guarda en SQLite la página y posición de cada candidato. También considera los juegos activos anteriores para no perder títulos relevantes por un cambio repentino del ranking. Cada identificador se valida con [Steam Store appdetails](https://store.steampowered.com/api/appdetails?appids=1245620&cc=us&l=english): solo se incorporan entradas de tipo `game` con imagen válida, precio de Steam y al menos una oferta reciente de otra tienda. El catálogo termina al alcanzar 500 juegos. No se confía en el título de SteamSpy para la ficha.

`data/nexo.sqlite` es la fuente persistente. `data/catalog.json` se genera desde esa base para que GitHub Pages sirva el catálogo sin ejecutar un servidor. La lista no está escrita en los archivos JavaScript de la interfaz. El esquema y la justificación están en [ADR-001](adr-001-sqlite-catalog.md).

El script guarda el nombre, ID de Steam, precio en USD para `cc=us`, fecha de lanzamiento, puntuación Metacritic cuando Steam la ofrece, total de logros, seis logros destacados como máximo, URL de portada y seis capturas como máximo. La reconstrucción automática se ejecuta los lunes y la caché de respuestas de SteamSpy y Steam Store vence tras siete días. Una oferta anterior de otra tienda solo puede completar la selección si se observó durante los últimos siete días; conserva su fecha original. Si falla la validación de 500 juegos, conserva la última publicación. El sitio carga las imágenes de la CDN de Steam bajo demanda. Se intenta el póster `library_600x900.jpg` y, si no existe, se muestra la imagen alternativa devuelta por Steam Store. No se almacenan imágenes binarias en GitHub.

`scripts/update_steam_reviews.py` añade una segunda valoración: el porcentaje de votos positivos de usuarios de Steam, calculado con los recuentos públicos de SteamSpy. Guarda puntuación, número de votos y fecha real de la respuesta en SQLite; el JSON público sale de esa base. Consulta primero dos páginas del ranking y completa por ID los juegos ausentes. La actualización se ejecuta los miércoles y tras la reconstrucción semanal. Es una métrica de usuarios, distinta de Metacritic; se presenta como «Usuarios de Steam» en la ficha y junto a la plataforma de cada tarjeta.

`scripts/update_platforms.py` vincula lanzamientos de consola por el ID exacto de Steam en Wikidata (`P1733`) y sus plataformas (`P400`). Conserva cada afirmación y su fecha en `game_platforms` de SQLite; si un ID apunta a varios juegos de Wikidata, no lo asigna automáticamente. La web muestra las plataformas de lanzamiento, pero **todos los precios actuales son de PC**. El filtro de plataforma indica dónde se lanzó el juego; no implica que el precio mostrado sea de esa consola. La captura se renueva semanalmente. La decisión y sus límites están en [ADR-003](adr/003-plataformas-wikidata.md).

Las duraciones se enlazan contra el [conjunto comunitario HLTB para LaunchBox](https://github.com/johagan94/hltb-dataset-plugin), capturado el 27 de marzo de 2026. El script exige una entrada `game`, plataforma PC y nombre normalizado único y exacto. No se hacen emparejamientos aproximados para no atribuir las horas de otra edición. Solo se publican hasta tres valores de horas y el ID de HLTB de las coincidencias. El archivo completo queda en la caché local y no se publica. Esta captura es histórica y su repositorio indica que la licencia del conjunto de datos está pendiente de definición; revisar las condiciones de uso antes de redistribuirlo fuera del proyecto académico.

## Precios y límites

El precio de Steam es una referencia de la región de EE. UU., capturada al generar `data/catalog.json`. La disponibilidad y el valor cambian según país. `scripts/update_gog_offers.py` recorre el catálogo oficial paginado de GOG para EE. UU. y vincula los juegos por título exacto normalizado. `scripts/update_store_offers.py` consulta a CheapShark en lotes de 20 identificadores de Steam y guarda las ofertas de sus otras tiendas activas. Ambas fuentes se guardan en `retailer_offers` de SQLite, se exportan con el catálogo y se renuevan semanalmente. Los ocho juegos del piloto `live-data.js` tienen además una captura diaria. Al abrir una ficha, el navegador puede consultar CheapShark directamente y conservar esas observaciones durante 30 minutos. El filtro reúne las ofertas publicadas y las observadas en ese navegador. Solo aparecen tiendas que devuelven ofertas para juegos de este catálogo. Las tasas monetarias de Hacienda tienen fecha propia y no convierten un precio regional en un precio garantizado para Costa Rica.

La API de `appdetails` tiene un límite de consultas observado por la comunidad. El script espera 1,75 segundos entre solicitudes nuevas y conserva respuestas en `.catalog-cache/`. Si una petición falla, se puede ejecutar de nuevo para reanudar. La captura agregada usa lotes de 20 juegos, solicitudes secuenciales espaciadas al menos 2,5 segundos y una ejecución semanal; ante HTTP 429 espera antes de reintentar. Si falla algún lote, conserva la captura anterior. La captura de GOG utiliza su catálogo público paginado.

El historial se conserva en `offer_history` de SQLite y se publica como `data/price-history.json` con una ventana de 90 días. Cada punto contiene juego, tienda, precio original en USD, fuente y fecha de captura. Las revisiones fechadas de `live-data.js` se importaron una vez mediante `python scripts/import_pilot_history.py --backfill-git`; el workflow archiva las capturas nuevas a diario. Las capturas de GOG y de las demás tiendas se agregan semanalmente. Una sola captura aparece como punto, sin línea de tendencia ni mínimo histórico anterior inventado.

Cada oferta de la ficha muestra su fecha de captura cuando está disponible. La oferta de Steam usa la fecha de la captura del catálogo; las ofertas guardadas de minoristas usan su fecha en SQLite; una consulta hecha al abrir la ficha conserva la hora de esa consulta en el navegador.

Steam Store no siempre publica precio, logros o capturas. En esos casos se muestra «Sin datos» o «Precio no disponible». La interfaz no calcula descuentos si no hay precio original y precio actual válidos.

## Pendiente para la entrega del curso

Faltan fuentes de precios para PlayStation, Xbox y Switch, un minorista obligatorio, duración actualizada, conciliación validada de títulos entre tiendas y ranking diario de búsquedas. El motor semanal de una fuente ya ejecuta lotes de forma secuencial o concurrente; el núcleo de los tres modos completos todavía necesita adaptadores y capturas de todas las fuentes. El catálogo de 500 fichas no implica que las demás partes estén completadas.
